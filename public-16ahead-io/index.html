How it works

Orchestration and context.

Every request to 16Ahead becomes a Mission: a plan of ordered steps. Each step says who does it: a person, the Marketing Assistant or 16Ahead. This page walks through how a Mission is planned, run, watched and reported.

1No work without a plan.Every Mission carries ordered steps, and each step says who does it.
2Nothing is ever stuck.Every step has a rule for when it counts as stuck and what happens next. When a step can't be done by software, it becomes a person's step with the reason. It never just fails.
3Every finished Move has a report.What was done, who did each step, when it happened and what came out of it.

02 · The gate

Every request passes one gate.

A request can be typed to an assistant, made by creating a Move, or come from a signal or a schedule. One assessment call works out the outcome you want, then whether reaching it needs a plan. It does if any of these is true.

03 · The plan

Every step has an owner and a rule for when it's stuck.

A plan is an ordered set of steps with dependencies. Each step is one of five kinds. A when condition on earlier outputs makes branches possible: if they reply, do this; if not, follow up.

tool16Ahead or the Marketing Assistant runs a registered tool.
taskA person does it. Done when they mark it, or when evidence shows up, like the document being uploaded.
approvalA person says yes or no to something that was prepared for them.
waitWaits for an event, with a timeout. The output says which happened: replied, no reply, bounced.
decisionThe plan needs one answer from a person, such as "Which Regina?"
{
  id: "route1",
  title: "Find Regina's best contact route",
  owner: "16ahead",        // "person" | "marketing" | "16ahead"
  kind: "tool",            // tool | task | approval | wait | decision
  tool: "network.findContactRoute",
  input: { person: "$step:who1.person" },
  dependsOn: ["who1"],
  when: "",                // e.g. "$step:watch1.outcome == 'no_reply'"
  doneWhen: "A verified email or a warm-intro path",
  stuckAfter: "P2D",       // ISO duration once runnable
  onStuck: "escalate",     // remind | replan | reassign | escalate
  whyNotMe: "",            // set when handed to a person
  status: "pending",       // pending | running | waiting | done | skipped | failed
  resultSummary: "",       // one line for the report
  finishedBy: null         // who actually did it
}
One source of truth.The Mission record holds the steps, outputs, its origin and who it's for. Every surface reads the same Mission through one shared plan strip. Records that start a Mission keep a small summary so lists never need a second read.
Never planless.A Mission starts in planning. If planning fails or times out, it gets a one-step fallback: a task for the requester, "Plan this," with the reason attached. An outage can't block work.
You can edit it.Reorder, reassign an owner or delete a step. The plan is re-validated and the edit is recorded.
04 · The capability catalog

Plans are built from every space's tools.

Every tool in every space declares what it does, its typed inputs and outputs, its effect and its access level. A Move created in Moves can use Network, Find, Docs and Pulse in one plan. Adding a tool to any space makes it available to every Mission at once.

The planner is given the two or three closest past plans as references and adapts them. When a Mission finishes well and nobody had to rework the plan much, it is saved as a new example for that business.

{
  name: "network.findContactRoute",
  product: "network",
  lane: "16ahead",         // which assistant may run it
  does: "Finds a verified email or warm-intro path for a person",
  inputs: {...}, outputs: {...},   // typed, so $step: references are checked
  effect: "read",          // read | create | send | wait | change
  access: "direct",        // direct | approval | never
  counts: {...},           // allowance and cost counters
  wraps: ["GET /network/..."]      // the documented API operations it uses
}

06 · The watchdog

Nothing stays stuck.

Every 30 minutes a scheduled job reads the Missions that are due for a check and acts on every step past its time limit.

0Stuck countThe watchdog's job is to keep this at zero. It's the gauge on the Moves cockpit.
Person task overdueremindOne nudge to the assignee. On the second miss, escalate to the project lead.
Tool step failed twicereplanThe remaining steps are rewritten around the failure: a different contact route, or a person step.
Wait step timed outbranchNot stuck. The timeout is an outcome, and the plan takes the "no reply" branch.
Assignee gonereassignRemoved or on leave: the step goes to the project lead, who is told why.
Waiting on an answer for 2+ daysescalateAsk again once, then escalate.
Waiting on a person is a state, not stuck. Signing a contract, attending a meeting or logging into a bid portal belongs to a person. That's fine as long as a named person has it, knows why, and the watchdog is tracking it. Work is stuck only when its current step has no owner, no next action, or is past due with nobody told. Every step is either a tool from one of the spaces or a named person with a reason. There is no third option.
07 · The approval gate

Nothing goes out without you.

Every send is an approval step until you decide auto-send is ready. That is your call. Routine, reversible work happens on its own; approvals are for exceptions, risk, spend and policy limits.

08 · The report

Every finished Move has a report.

When the last step finishes, the report lists what was done, who did each step, when, and what came out of it. The last line says how much was done for you and how little of your time it took.

09 · The standard

A feature that only reports information isn't finished.

Every capability answers one question: what work can 16Ahead complete without waiting for you? It is complete only when 16Ahead can do all six.

01Observe a business condition or signal.
02Interpret what it means.
03Choose a course of action.
04Execute it safely.
05Measure the outcome.
06Adapt using the result.
An analyst says"LinkedIn engagement dropped 37%."
16Ahead says"LinkedIn engagement dropped 37%. I analyzed the last 40 posts, found technical screenshots outperform quote cards, generated five replacement posts, scheduled them for Tuesday and Thursday, and will update the strategy after results come in."
